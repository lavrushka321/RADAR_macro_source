# RADAR_macro_source

```bash
pip install -r requirements.txt
python main.py
```

`pynput`, `pydirectinput` и `mss` больше не нужны: клавиши читаются через
`GetAsyncKeyState`, кадры — через `PrintWindow` окна Roblox.

## Управление

| Клавиша | Действие |
| --- | --- |
| ESC | Полное завершение |
| F (удерживать) | RADAR: сканирование зоны вокруг курсора |
| Q | Тепловизор: вся клиентская область Roblox (повторно — выключить) |
| Y | Переключить показ тепловизора: мини-окно `RADAR_VIEW` ↔ полупрозрачный оверлей на весь экран |
| H | Полноэкранный поиск целей по активному профилю, независимо от тепловизора (повторно — выключить) |
| V | Слежение за целью: `LOCK` → цель радара `F` → главная цель полного поиска `H` |
| G | Переключить профиль поиска (для радара `F` и полного поиска `H`) |
| Z | RADAR_VIEW: увеличить окно и картинку в 2 раза (повторно — обычный масштаб) |
| RMB (удерживать) | Цифровой TV-прицел ×2 вокруг курсора/цели: показывает игру без `Q`, тепловизор с `Q` |
| T | Захватить/сменить цель рядом с курсором по внешнему виду (работает при `TARGETS: 0` и без поиска; повторно на текущей цели — снять `LOCK`) |
| N | Включить/выключить удержание выбранной цели в центре экрана во время WASD |
| Ё | Свернуть / развернуть оверлей |

Все клавиши меняются в `BINDS` в `~/.radar_macro/config.json`.

В правом верхнем углу `RADAR_VIEW` есть кликабельная кнопка `UI: NEW` /
`UI: NORMAL`. Она переключает `INTERFACE_MODE` и сохраняет выбор в конфиг.
`NEW` — полный TV-интерфейс без крестика/точки в самом центре; `NORMAL` —
обычный системный курсор без TV-обвязки, при сканировании снова рисуется
зелёный круг радара, а в мини-окне — простой крест и зелёная точка.
RMB-линза работает в обоих режимах, но в `NORMAL` остаётся только тонкая рамка.

`H` всегда открывает `RADAR_VIEW`, даже если в конфиге стоит
`SHOW_RADAR_VIEW: false`. `Q` делает это только в режиме `window`; в режиме
`overlay` тепловизор рисуется поверх экрана и мини-окно для него не нужно.
Когда активные режимы больше не требуют окна, оно закрывается.

## Поиск и окно RADAR_VIEW

- Поиск захватывает **только клиентскую область окна Roblox** (оконный режим).
  Рабочий стол, другие окна и собственный оверлей в кадр не попадают.
- `F` сканирует квадрат `SQUARE_SIZE` вокруг курсора, обрезанный по границам
  окна. `RADAR_VIEW` показывает **сырую карту движения (absdiff) до threshold,
  blur и морфологии**, усиленную в `MOTION_MAP_GAIN` раз (по умолчанию 8).
- `Q` показывает **чёрно-белую (white-hot) тепловую карту всего клиента
  Roblox**. В режиме `window` (по умолчанию) кадр вписывается в `RADAR_VIEW`
  с сохранением пропорций (чёрные поля по краям), поэтому видно всё окно, а не
  только область вокруг курсора. В режиме `overlay` весь экран затемняется на
  `bg_alpha`, а тепловой слой рисуется прямо поверх окна Roblox; мини-окно для
  такого показа не нужно. `Y` (`key_thermal_mode`) переключает режимы на лету и
  сохраняет выбор в `THERMAL_MODE` (`window` / `overlay`).
- `H` включает **полноэкранный поиск целей** по всему клиенту Roblox с активным
  профилем `SEARCH_PROFILES`. Режим не зависит от `Q`: его можно включить как
  вместе с тепловизором, так и отдельно. Рамки целей рисуются в `RADAR_VIEW` и
  на игровом оверлее. Если включены оба режима, поверх тепловой карты видны
  рамки полного поиска.
- `Z` (`key_zoom`) переключает масштаб `RADAR_VIEW`: окно и картинка
  увеличиваются в 2 раза (400×400 → 800×800), повторное нажатие возвращает
  обычный размер. Увеличение касается только отображения, поиск и координаты
  целей не меняются; если окно упирается в край экрана, оно сдвигается внутрь.
- `RMB` (`key_zoom_hold`) удерживает цифровой TV-прицел ×2. Прицел берёт область
  вокруг курсора до захвата и вокруг цели после `LOCK`. Без `Q` внутри прицела
  показывается чёрно-белая картинка игры, с `Q` — увеличенный тепловизор. Это
  только цифровое увеличение отображения: камера Roblox не двигается.
- TV-прицел рисуется от курсора, а после захвата — от центра цели: длинный
  крест, внутренний квадрат и внешние угловые скобы. Крестик и точка в самом
  центре убраны. Линии целей F/H/LOCK тоже идут от курсора/цели, а не от центра
  экрана.

## Тепловизор и полный поиск

- `Q` (`key_thermal`) — чёрно-белая тепловая карта всего окна Roblox. Порог,
  размер точки, шаг выборки и фон настраиваются Num-клавишами (см. ниже). Карта
  строится по разнице кадров и подсвечивает движение white-hot (белым по
  тёмному), без цветных палитр. `bg_alpha` задаёт яркость фона в режиме
  `window` и степень затемнения экрана в режиме `overlay`.
- `Y` (`key_thermal_mode`) — место показа тепловизора: `window` (мини-окно
  `RADAR_VIEW`) или `overlay` (полупрозрачный слой на весь экран). В режиме
  `overlay` затемняется весь экран, а горячие пиксели рисуются поверх клиента
  Roblox; рамки `H`, радара `F` и `LOCK` остаются сверху.
- `H` (`key_fullscan`) — полноэкранный поиск целей. Использует те же
  `SEARCH_PROFILES`, что и радар `F`; `G` переключает профиль для обоих
  режимов. Подтверждение целей (`min_hits`, `max_misses`, `match_dist`) и
  фильтры шума работают так же, как в оконном радаре.
- Режимы независимы: можно оставить только тепловизор (`Q`), только поиск
  (`H`) или включить оба. Захват кадра общий, поэтому при включённых `Q` и `H`
  окно Roblox не снимается дважды. В режиме `overlay` при включённом `H`
  мини-окно показывает карту движения и рамки, а тепловизор остаётся на экране.
- Полный поиск рисует рамки на всём игровом экране (зелёные) и в `RADAR_VIEW`.
  Главная цель полного поиска — самая крупная подтверждённая рамка.
- При включённом `V` приоритет ведения: ручной `LOCK` → главная цель радара
  `F` → главная цель полного поиска `H`. Если `F` отпущена, но `H` включён,
  `V` ведёт главную цель полного поиска. Сам по себе `H` слежение не включает.

## Ручной захват цели

`T` (`key_capture`) ищет цель **рядом с курсором**, а не строго под ним.
Сначала используются готовые рамки `F`/`H` в радиусе 180 px, затем локальный
поиск по контрасту/краям в окрестности курсора. Из найденного места вырезается
шаблон `template_size`×`template_size`, и дальше цель ведётся по внешнему виду,
а не по детектору движения. Поэтому захват работает и при `TARGETS: 0` —
например, для неподвижного вертолёта. Захват работает независимо от `F`: при
отпущенной `F` рамка `LOCK` продолжает обновляться и искать цель в фоне, но
слежение `V` автоматически не включается. `V` можно включить вручную — тогда
курсор будет вести цель даже без радарного поиска.

Смена и снятие цели:

- наведите курсор на другую цель и нажмите `T` — `LOCK` переключится на неё без
  промежуточного снятия;
- если рядом с текущей целью есть другая рамка `F`/`H`, повторный `T` переключит
  на неё;
- если других целей рядом нет, повторный `T` на текущей цели снимает `LOCK`.

Если включён `V`, курсор постоянно ведётся за `LOCK`, поэтому для наведения на
другую цель на время выключите `V` (или `N`). Сам `LOCK` при этом сохраняется.

Защита от срыва:

- при ручном захвате курсор ведётся за `LOCK`, а не за самым крупным блобом,
  поэтому трассеры и вспышки не перетягивают наведение;
- поиск шаблона ограничен окрестностью прошлой позиции (`search_margin`);
  после промаха раз в два скана делается более широкий поиск (`wide_margin`)
  с повышенным порогом `wide_match_min`;
- короткие перекрытия (трассер прошёл через цель) переживаются: до
  `max_misses` сканов позиция экстраполируется по последней скорости, но
  удерживается рядом с последней подтверждённой точкой;
- когда `max_misses` исчерпан, захват не сбрасывается сразу: ещё
  `lost_timeout` секунд шаблон ищется в радиусе `lost_margin` вокруг последней
  подтверждённой позиции с порогом `lost_match_min`. Если цель нашлась —
  ведение продолжается, иначе захват снимается;
- шаблон обновляется только при совпадении не ниже `update_score` (а после
  lost-поиска — только при очень уверенном совпадении), чтобы фон и трассеры
  не «впечатывались» в эталон.

Параметры — в `LOCK_SETTINGS` конфига: `template_size`, `search_margin`,
`wide_margin`, `match_min`, `wide_match_min`, `max_misses`, `lost_margin`,
`lost_timeout`, `lost_match_min`, `update_score`.

`V` при активном захвате только включает/выключает ведение курсора и **не
снимает** `LOCK`. Если при захвате поиск активен и слежение было выключено,
`T` включит его автоматически, а после повторного `T` или срыва снова
выключит; если слежение было включено до захвата, оно останется включённым.
Если захват сделан без поиска, `V` автоматически не включается; включённое
вручную после захвата слежение снятие `T` не выключает. `N` (`key_center_hold`)
включает удержание выбранной цели в центре экрана: игра продолжает обрабатывать
WASD, а макрос каждый тик плавно компенсирует смещение цели. `N` работает и с
ручным `LOCK`, и с главной целью `F`/`H`, независимо от `V`. Для обзора камеры
в третьем лице макрос на время `N` сам зажимает RMB (`CENTER_AUTO_RMB`, по
умолчанию `true`); этот синтетический RMB не включает RMB-линзу. Если игра в
первом лице или RMB нужен для линзы, поставьте `CENTER_AUTO_RMB: false`.
Коррекция работает только когда окно Roblox активно и курсор не над
`RADAR_VIEW`; если цель не приближается к центру, макрос делает паузу, чтобы
курсор не уезжал бесконечно. `Ё` и сворачивание снимают захват. Отпускание `F`
не снимает захват и не сбрасывает шаблон:
хардлок продолжает искать цель и обновлять рамку `LOCK` в фоне. Если `V`
включён, курсор продолжает вести цель; если выключен, рамка следует за целью
без движения курсора.

## Профили поиска

Профили лежат в `SEARCH_PROFILES` в конфиге, активный — в `ACTIVE_PROFILE`.

- `precision` (по умолчанию) — максимальная точность: низкий порог, без
  подтверждения кадров и без фильтров формы.
- `noise` — защита от помех на подвижном фоне:
  - `adaptive` — порог сам поднимается, когда двигается большая часть кадра
    (поворот камеры/трава), но никогда не опускается ниже базового `threshold`;
  - `open` + `min_seed` — одиночные пиксели и мелкие пятна шума удаляются
    **до** дилатации, иначе одно пятно раздувается в ложный блоб;
  - `min_fill`/`max_aspect` — отсекают разреженные и вытянутые блобы (трава,
    ветки, линии HUD), оставляя компактные цели;
  - `max_motion_ratio` — при почти полной смене кадра (резкий поворот камеры)
    скан пропускается;
  - `min_hits` + `match_dist` — цель должна подтвердиться на 3 сканах рядом
    с прошлой позицией; `max_misses` разрешает один пропущенный скан, чтобы
    прогресс не сбрасывался из-за мигания цели.

Активный профиль применяется и к радару `F`, и к полному поиску `H`.
Переключение на лету — клавиша `key_profile` (по умолчанию `G`); выбор
сохраняется в конфиг. Настройки тепловизора (Num +/-/8/2/6/4/9/7) тоже
сохраняются при выключении тепловизора; Num 9/7 меняют яркость фона в режиме
`window` и степень затемнения в режиме `overlay`.

## Конфиг

`~/.radar_macro/config.json` создаётся автоматически, при обновлении дополняется
новыми ключами и чистится от устаревших. Битый файл сохраняется рядом как
`config.json.bad`, после чего пишутся дефолты.

`CONFIG_VERSION` хранит версию схемы. При переходе на версию 3 профиль `noise`
один раз заменяется новыми настроенными значениями (у него появились
адаптивный порог и фильтры шума), `precision` и остальные настройки
сохраняются. Новые бинды `key_fullscan` (по умолчанию `H`), `key_thermal_mode`
(по умолчанию `Y`), `key_zoom_hold` (по умолчанию `RMB`) и `key_center_hold`
(по умолчанию `N`) добавляются в `BINDS` автоматически. Ключ `THERMAL_MODE`
(`window` или `overlay`) также появляется автоматически; по умолчанию —
`window`. Для `key_zoom_hold` поддерживаются мышиные имена `LMB`, `RMB`, `MMB`,
`XBUTTON1`, `XBUTTON2`. Ключ `INTERFACE_MODE` (`new` или `normal`, по умолчанию
`new`) тоже добавляется автоматически и меняется кнопкой в `RADAR_VIEW`.
`CENTER_AUTO_RMB` (по умолчанию `true`) разрешает макросу зажимать RMB на время
`N`, чтобы камера Roblox слушала относительное движение мыши в третьем лице.

Текущая версия — **beta-3.4**.
